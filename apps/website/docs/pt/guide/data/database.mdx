# Banco de dados

Todos os dados estão em um arquivo SQLite. O app o cria na primeira vez que inicia.

```text
~/Library/Application Support/DailyZGT/daily-zgt.sqlite
```

O app usa o modo WAL. Enquanto o app roda, você pode ver mais dois arquivos ao lado do banco de dados, com as terminações `-wal` e `-shm`.

## Leia o banco com sqlite3

O macOS inclui o `sqlite3`. Liste as tabelas.

```bash
sqlite3 "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" ".tables"
```

Leia as prioridades abertas. A opção `-readonly` garante que você não mude nada.

```bash
sqlite3 -readonly "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" \
  "select title, level, list, due_at from priority where done_at is null"
```

Leia as notas.

```bash
sqlite3 -readonly "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" \
  "select scope, period, body from note"
```

Leia os ajustes que o app guarda no banco de dados.

```bash
sqlite3 -readonly "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" \
  "select key, value from app_state"
```

:::warning
Não edite o banco de dados enquanto o app roda. Use `-readonly` nas consultas.
:::

## As seis tabelas

As datas são texto ISO 8601 em horário local, sem deslocamento de fuso horário, por exemplo `2026-10-12T16:00:00`.

| Tabela | O que ela guarda |
|---|---|
| `priority` | 12 colunas: `id`, `title`, `note`, `level` (`high`, `medium`, `low`), `list` (`today`, `week`), `due_at` (null significa sem prazo), `done_at` (null significa aberta), `position`, `created_at`, `updated_at`, `repeat_rule` (`none`, `daily`) e `repeat_series_id` (null significa uma série de uma única prioridade) |
| `subtask` | `id`, `priority_id`, `title`, `done_at`, `position`, `created_at`. As linhas somem quando a prioridade delas some. |
| `note` | `scope` (`day`, `week`), `period` (`2026-10-12` ou `2026-W42`), `body`, `updated_at`. Uma linha para cada scope e período. |
| `alert` | `id`, `priority_id`, `kind` (`before_30m`, `at_due`, `snooze`), `fire_at`, `status` (`scheduled`, `delivered`, `snoozed`, `cancelled`). As linhas somem quando a prioridade delas some. |
| `priority_event` | `id`, `priority_id`, `at`, `type` (`created`, `edited`, `moved`, `done`, `restored`, `subtask_done`). É o histórico. |
| `app_state` | `key`, `value` (texto JSON). Veja a lista de chaves abaixo. |

As chaves de `app_state` são:

| Chave | O que ela guarda |
|---|---|
| `open_tab` | A aba aberta, `priorities` ou `notes` |
| `open_scope` | A lista aberta, `today` ou `week` |
| `done_open` | `true` quando **Hechas** está aberta |
| `today_limit` | `true` quando o limite de 5 está ligado. O valor inicial é `false`. |
| `menu_bar_title` | `true` quando a barra de menus mostra o título. O valor inicial é `true`. |
| `alert_permission_asked` | `true` depois que o app pediu a permissão de notificações |

Uma chave que não está na tabela tem o valor inicial.

O ajuste de iniciar ao abrir a sessão e o atalho global não estão no banco de dados. Veja [Ajustes](/guide/use/settings).

## Migrações

O app muda o esquema com duas migrações, nesta ordem:

1. `001_create_tables` cria as seis tabelas.
2. `002_add_repeat_to_priority` adiciona as colunas `repeat_rule` e `repeat_series_id` a `priority`. Veja [Repetir todo dia](/guide/use/repeat).

O app executa cada migração uma única vez. O comando `.tables` também lista uma sétima tabela, `grdb_migrations`. O GRDB, a biblioteca de SQLite do app, a usa para acompanhar as migrações que já rodaram. Não a edite. Leia-a com este comando:

```bash
sqlite3 -readonly "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" \
  "select identifier from grdb_migrations"
```

## Mudanças vindas de fora

O app vigia o arquivo `daily-zgt.sqlite-wal`. Quando outro programa escreve no banco de dados, o painel mostra a mudança. Por exemplo, uma mudança em uma nota aparece no campo da nota. Mesmo assim, não escreva no banco de dados enquanto o app roda.

## Backup

Copie o arquivo com o app parado.

1. Pare o app. Veja [Compilar e executar](/guide/getting-started/build-and-run).
2. Copie o arquivo do banco de dados para uma pasta segura.

```bash
cp "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" ~/daily-zgt-backup.sqlite
```

Se ao lado do banco de dados houver arquivos com as terminações `-wal` e `-shm`, copie-os também.

Para restaurar, pare o app e copie o backup sobre o arquivo do banco de dados.

O backup não guarda o ajuste de iniciar ao abrir a sessão nem o atalho global.
