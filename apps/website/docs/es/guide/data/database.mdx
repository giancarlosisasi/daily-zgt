# Base de datos

Todos los datos están en un archivo SQLite. La app lo crea la primera vez que inicia.

```text
~/Library/Application Support/DailyZGT/daily-zgt.sqlite
```

La app usa el modo WAL. Mientras la app corre, puedes ver dos archivos más junto a la base de datos, con las terminaciones `-wal` y `-shm`.

## Lee la base con sqlite3

macOS incluye `sqlite3`. Lista las tablas.

```bash
sqlite3 "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" ".tables"
```

Lee las prioridades abiertas. La opción `-readonly` asegura que no cambies nada.

```bash
sqlite3 -readonly "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" \
  "select title, level, list, due_at from priority where done_at is null"
```

Lee las notas.

```bash
sqlite3 -readonly "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" \
  "select scope, period, body from note"
```

Lee los ajustes que la app guarda en la base de datos.

```bash
sqlite3 -readonly "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" \
  "select key, value from app_state"
```

:::warning
No edites la base de datos mientras la app corre. Usa `-readonly` para las consultas.
:::

## Las seis tablas

Las fechas son texto ISO 8601 en hora local, sin desfase de zona horaria, por ejemplo `2026-10-12T16:00:00`.

| Tabla | Qué guarda |
|---|---|
| `priority` | 12 columnas: `id`, `title`, `note`, `level` (`high`, `medium`, `low`), `list` (`today`, `week`), `due_at` (null significa sin fecha límite), `done_at` (null significa abierta), `position`, `created_at`, `updated_at`, `repeat_rule` (`none`, `daily`) y `repeat_series_id` (null significa una serie de una sola prioridad) |
| `subtask` | `id`, `priority_id`, `title`, `done_at`, `position`, `created_at`. Las filas se van cuando se va su prioridad. |
| `note` | `scope` (`day`, `week`), `period` (`2026-10-12` o `2026-W42`), `body`, `updated_at`. Una fila por cada scope y periodo. |
| `alert` | `id`, `priority_id`, `kind` (`before_30m`, `at_due`, `snooze`), `fire_at`, `status` (`scheduled`, `delivered`, `snoozed`, `cancelled`). Las filas se van cuando se va su prioridad. |
| `priority_event` | `id`, `priority_id`, `at`, `type` (`created`, `edited`, `moved`, `done`, `restored`, `subtask_done`). Es el historial. |
| `app_state` | `key`, `value` (texto JSON). Mira la lista de claves abajo. |

Las claves de `app_state` son:

| Clave | Qué guarda |
|---|---|
| `open_tab` | La pestaña abierta, `priorities` o `notes` |
| `open_scope` | La lista abierta, `today` o `week` |
| `done_open` | `true` cuando **Hechas** está abierta |
| `today_limit` | `true` cuando el límite de 5 está encendido. El valor inicial es `false`. |
| `menu_bar_title` | `true` cuando la barra de menús muestra el título. El valor inicial es `true`. |
| `alert_permission_asked` | `true` después de que la app pidió el permiso de notificaciones |

Una clave que no está en la tabla tiene su valor inicial.

El ajuste de iniciar al abrir sesión y el atajo global no están en la base de datos. Mira [Ajustes](/guide/use/settings).

## Migraciones

La app cambia el esquema con dos migraciones, en este orden:

1. `001_create_tables` crea las seis tablas.
2. `002_add_repeat_to_priority` agrega las columnas `repeat_rule` y `repeat_series_id` a `priority`. Mira [Repetir cada día](/guide/use/repeat).

La app ejecuta cada migración una sola vez. El comando `.tables` también lista una séptima tabla, `grdb_migrations`. GRDB, la biblioteca de SQLite de la app, la usa para seguir las migraciones que ya corrieron. No la edites. Léela con este comando:

```bash
sqlite3 -readonly "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" \
  "select identifier from grdb_migrations"
```

## Cambios desde fuera

La app vigila el archivo `daily-zgt.sqlite-wal`. Cuando otro programa escribe en la base de datos, el panel muestra el cambio. Por ejemplo, un cambio en una nota aparece en el campo de la nota. Aun así, no escribas en la base de datos mientras la app corre.

## Copia de seguridad

Copia el archivo con la app detenida.

1. Detén la app. Mira [Compilar y ejecutar](/guide/getting-started/build-and-run).
2. Copia el archivo de la base de datos a una carpeta segura.

```bash
cp "$HOME/Library/Application Support/DailyZGT/daily-zgt.sqlite" ~/daily-zgt-backup.sqlite
```

Si junto a la base de datos hay archivos con las terminaciones `-wal` y `-shm`, cópialos también.

Para restaurar, detén la app y copia la copia de seguridad sobre el archivo de la base de datos.

La copia de seguridad no guarda el ajuste de iniciar al abrir sesión ni el atajo global.
